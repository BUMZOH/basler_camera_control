# タスクマネージャーでアプリのコマンドライン引数を調べる方法

## 1. 概要

Windowsアプリケーションの中には、実行ファイル（`.exe`）を
単独で起動するだけでは正常に動作せず、起動時に
**コマンドライン引数**を必要とするものがあります。

例えば今回確認したKEYENCE XG-X Simulatorでは、
正常起動時のコマンドラインに次の2つが含まれていました。

``` text
XG-X Simulator.exe
XG_SimBoot.dat
```

つまり概念的には、

``` text
"XG-X Simulator.exe" "XG_SimBoot.dat"
```

という形でSimulatorが起動されています。

このような情報は、特別なプロセス解析ソフトを使用しなくても、
Windowsの**タスクマネージャー**から確認できます。

------------------------------------------------------------------------

## 2. コマンドラインとは

例えば次のような起動方法があったとします。

``` text
app.exe config.dat
```

この場合、

``` text
app.exe
```

が実行するプログラムで、

``` text
config.dat
```

が起動時に渡している引数です。

ほかにもアプリによって、

``` text
app.exe /debug
app.exe -project ABC
app.exe "C:\Data\config.dat"
```

のような形式があります。

GUIアプリケーションでも、起動時にこのような情報を
受け取って動作することがあります。

------------------------------------------------------------------------

## 3. タスクマネージャーで確認する手順

### 手順1：対象アプリを正常な方法で起動する

まず、調査したいアプリを通常の正しい方法で起動します。

今回のXG-X Simulatorであれば、 XG-X
VisionEditorからSimulatorを正常に起動します。

重要なのは、

> **正常に動いている状態のプロセスを観察する**

ことです。

------------------------------------------------------------------------

### 手順2：タスクマネージャーを起動する

Windowsのタスクマネージャーを開きます。

例えば、

``` text
Ctrl + Shift + Esc
```

で直接起動できます。

------------------------------------------------------------------------

### 手順3：「コマンド ライン」列を表示する

タスクマネージャーで、対象プロセスの **コマンド ライン**を表示します。

Windowsのバージョンや表示画面によって操作方法は多少異なりますが、
「詳細」画面などでは列の設定から

``` text
コマンド ライン
```

を追加できます。

今回確認した環境では「プロセス」画面にも 「コマンド
ライン」列を表示できました。

------------------------------------------------------------------------

### 手順4：対象プロセスを探す

今回の場合は、

``` text
XG-X Simulator (32 ビット)
```

を探します。

その「コマンド ライン」欄を確認します。

------------------------------------------------------------------------

### 手順5：exeの後ろを確認する

正常起動したXG-X Simulatorでは、
コマンドラインに概ね次のような内容が表示されました。

``` text
"C:\Program Files (x86)\KEYENCE\XG-X VisionEditor H1X\sim\XG-X Simulator.exe"
"C:\Users\...\XG-X VisionEditor\XG_SimBoot.dat"
```

ここで重要なのは、

``` text
XG-X Simulator.exe
```

だけではなく、その後ろに

``` text
XG_SimBoot.dat
```

が存在していることです。

これにより、

> XG-X Simulatorの起動時に\
> `XG_SimBoot.dat` が引数として渡されている

ことが分かります。

------------------------------------------------------------------------

## 4. 「引数が表示されている」だけでは必須とは限らない

ここは重要なポイントです。

タスクマネージャーで、

``` text
app.exe option
```

と表示されていても、

``` text
option
```

が必ず必要とは限りません。

単なるオプションの場合もあります。

したがって、調査は次の2段階で考えます。

``` text
1. 正常起動時のコマンドラインを観察する
                ↓
2. 同じ引数あり／なしで実際に起動して比較する
```

例えば、

``` text
XG-X Simulator.exe
```

だけでは正常起動せず、

``` text
XG-X Simulator.exe XG_SimBoot.dat
```

なら正常起動するのであれば、

``` text
XG_SimBoot.dat
```

が起動に必要な情報である可能性が非常に高くなります。

------------------------------------------------------------------------

## 5. コマンドプロンプトで再現する

タスクマネージャーでコマンドラインが分かったら、
次はコマンドプロンプトから同じ起動方法を試します。

今回の場合は次の形式です。

``` text
"XG-X Simulator.exeのフルパス" "XG_SimBoot.datのフルパス"
```

実際の例：

``` text
"C:\Program Files (x86)\KEYENCE\XG-X VisionEditor H1X\sim\XG-X Simulator.exe" "C:\...\XG_SimBoot.dat"
```

これで正常起動できれば、

``` text
タスクマネージャーで発見した起動条件
                ↓
コマンドプロンプトから再現成功
```

となります。

------------------------------------------------------------------------

## 6. Pythonから再現する

コマンドプロンプトから正常起動できたら、 Pythonの `subprocess`
でも同じ起動方法を再現できます。

``` python
import subprocess

subprocess.Popen(
    [
        SIMULATOR,
        BOOT_FILE,
    ]
)
```

このリストは概念的には、

``` text
[
    "XG-X Simulator.exe",
    "XG_SimBoot.dat",
]
```

となっています。

つまりタスクマネージャーで確認した、

``` text
"XG-X Simulator.exe" "XG_SimBoot.dat"
```

という起動方法をPythonから再現しているわけです。

------------------------------------------------------------------------

## 7. 調査の基本パターン

今後、別のアプリケーションで、

``` text
exeを直接ダブルクリックしても動かない
```

あるいは、

``` text
別のアプリから起動すると動くのに、
exe単独では動かない
```

という現象が発生した場合は、次の順番で調査できます。

``` text
正常な方法でアプリを起動
        ↓
タスクマネージャーを開く
        ↓
「コマンド ライン」を表示
        ↓
対象プロセスを探す
        ↓
exeの後ろに引数が付いていないか確認
        ↓
コマンドプロンプトで同じ起動方法を試す
        ↓
引数あり／なしを比較
        ↓
必要な起動条件を特定
        ↓
必要ならPython subprocessで再現
```

------------------------------------------------------------------------

## 8. 今回のXG-X Simulatorで分かったこと

今回のXG-X Simulatorでは、
正常起動しているプロセスのコマンドラインを確認すると、

``` text
XG-X Simulator.exe
```

の後ろに、

``` text
XG_SimBoot.dat
```

が渡されていることを確認できました。

そのためPythonでも、

``` python
subprocess.Popen(
    [
        SIMULATOR,
        BOOT_FILE,
    ]
)
```

という形で起動しています。

`XG_SimBoot.dat` の存在は、
単にファイル名から推測したものではありません。

**正常に動作しているXG-X Simulatorの起動状態を観察し、
そのコマンドラインを再現したものです。**

------------------------------------------------------------------------

## 9. 昔のSystem Explorerとの関係

以前はSystem Explorerなどのプロセス管理・解析ツールを使用して、
プロセスのコマンドラインを確認する方法がありました。

今回確認した内容については、
現在のWindowsではタスクマネージャーだけでも確認できます。

つまり今回必要だった、

``` text
このexeは何と一緒に起動されているのか？
```

という調査であれば、まずはタスクマネージャーを確認すれば十分です。

より詳しいプロセス解析が必要になった場合は、
専用のプロセス解析ツールを検討します。

------------------------------------------------------------------------

## 10. 覚えておくポイント

最も重要なのは次の考え方です。

> **正常に動いているプロセスの起動条件を観察して、
> 同じ条件を再現する。**

特に、

``` text
別アプリからなら起動できる
exe単独では起動できない
```

という場合は、

``` text
コマンドライン引数が渡されていないか？
```

を確認する価値があります。

その最初の調査手段として、 Windowsのタスクマネージャーは非常に手軽です。

------------------------------------------------------------------------

## 11. 今回の要点

``` text
正常起動
    ↓
タスクマネージャー
    ↓
コマンド ラインを確認
    ↓
exeの後ろの引数を発見
    ↓
コマンドプロンプトで再現
    ↓
Python subprocessで再現
```

XG-X Simulatorの場合は、

``` text
XG-X Simulator.exe
        +
XG_SimBoot.dat
```

という起動条件を確認できました。

この方法を覚えておけば、 今後ほかのWindowsアプリケーションでも
「どうやって起動されているのか」を調査する際に利用できます。
